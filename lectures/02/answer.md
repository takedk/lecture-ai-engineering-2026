### ファインチューニングが向く場面・向かない場面についての考察

今回の 4つの実験（演習・基礎・実装・発展）の結果から、ファインチューニング（SFT / LoRA）と検索（RAG / ツール呼び出し）の使い分けは以下のように整理できる。

1. **ファインチューニングが向く場面（「答え方・形式・振る舞い」の定着と推論コストの削減）**：
   - **出力形式や文体の強制**：演習・基礎・実装のすべてにおいて、プロンプトだけでは 0%〜24% しか守れなかった JSON スキーマ（`answer` と `needs_review` の2キー出力）が、わずか 10〜40ステップの LoRA 学習で **100%（21/21）** 遵守されるようになった。長い few-shot 例を毎回プロンプトに入れなくても、小さなモデル（`0.8B`）で決まった出力形式や簡潔な説明トーンを安定して出させたい場面に非常に向いている。
   - **大量リクエスト時のトークン単価・遅延の削減**：学習後はアダプタをベースモデルの重みにマージ（`merge_and_unload`）できるため、推論時の追加レイテンシがゼロになり、長い指示文を省いて高頻度に処理する分類・定型抽出タスクで「コスト＜効果」を出しやすい。

2. **ファインチューニングが向かない場面（「事実知識の注入」「頻繁に更新される情報」「根拠有無の厳密な判定」）**：
   - **固有の事実知識の記憶と別名・言い換えへの対応**：発展課題で `glossary_sft.jsonl`（116件）を学習させた結果、学習時と同一の質問形式（カテゴリ A）では 5/5 暗記できたものの、別名や言い回しを変えた質問（カテゴリ B）では 1/5 に急落し、`gemini-3.5-flash-lite` のような正確な固有名詞が架空のモデル名に化けた。少量の SFT で知識を重みに焼き込もうとすると、表面的なテンプレート暗記になりやすい。
   - **元の知識の忘却と「もっともらしい創作」の助長**：発展課題のカテゴリ C で確認されたとおり、用語集の文体に強く適合した結果、もともと知っていた一般用語（`DPO`）の説明が壊れ、存在しない「修了試験の合格点」や「lec99-final タグ」に対しても講座用語集のような口調で架空のルールを断定するようになった（講義スライドで紹介されていた Gekhman et al. 2024 の知見と一致する）。
   - **情報更新の運用コスト**：FAQ の締切や利用規約、用語集の定義が1行変わるたびに再学習と再評価を回すのは非効率である。

3. **実務での設計指針（検索・ツールとの組み合わせ）**：
   - 講座固有の用語定義や社内規約のような**事実知識（何を答えるか）**は、モデルに暗記させるのではなく `search_glossary` のような検索ツール（RAG / エージェントの Function calling）で外部から正確に取得してコンテキストに渡す。さらに「検索結果が 0件ならプログラム側で『記載なし（要確認）』に分岐する」仕組みと組み合わせることで、根拠なし質問へのハルシネーションを確実に防げる。
   - そのうえで、検索結果を受け取って**決まった JSON 形式やトーンに整形する振る舞い（どう答えるか）**に課題が残る場合や、小型モデルで高速・安価に処理したい場合に LoRA ファインチューニングを適用するのが最も効果的である。
